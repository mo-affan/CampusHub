{{ icon('database', 17) }} How MySQL stored it

Bookings made in CampusHub are written by the stored procedure inside one transaction. For this booking the call is:

CALL sp_create_booking({{ b.facility_id }}, {{ b.student_id if b.student_id else 'NULL' }}, {{ b.faculty_id if b.faculty_id else 'NULL' }},
  '{{ b.booking_date|date('%Y-%m-%d') }}', '{{ b.start_time|hm }}', '{{ b.end_time|hm }}', …, @id);

The procedure locks facility {{ b.facility_id }} with SELECT … FOR UPDATE, trigger trg_booking_before_insert checks the facility status and overlaps, and the transaction commits or rolls back. (Rows loaded from the sample-data scripts go through the same trigger, without the procedure.)

Cancelling only changes status to CANCELLED. The row stays for reporting, and cancelled rows are ignored by the overlap check.
